# Security audit coverage checkpoint — 2026-09-20

This is a working ledger, not an audit completion or certification claim.
The machine-readable inventory is `SECURITY-AUDIT-COVERAGE-2026-09-20.csv`,
generated by `scripts/security_inventory.py` with disposable configuration.
It currently lists 430 HTTP/WebSocket route-method entries and 412 root RPC
operations. The CSV marks entries pending until their authorization,
ownership, side effects, and negative tests have been individually reviewed.
In particular, a declared FastAPI dependency is not evidence that the
underlying root handler enforces account ownership.

## Entry-point classification still required

The route inventory found 405 route-method entries with direct
`get_identity` dependencies, 14 FileBrowser proxy methods and one WebSocket
with manual authentication, and 10 deliberately public entries (login,
health, branding reads and SPA/root). These are dependency observations, not
completed role/resource decisions. Scheduled tasks, listeners, installers,
native helpers, and asynchronous continuations still need dedicated rows.

The audit plan uses OWASP ASVS 5.0.0 Level 2 as the baseline and selected
Level 3 requirements for administration, isolation, authentication, secrets
and updates. A requirement-by-requirement ASVS/WSTG mapping is pending. No
claim of conformance should be made from this checkpoint.

## Verification limits

The sandbox cannot run systemd, network namespaces or real service sockets.
Unit tests use a disposable configuration. Bounded read-only host checks and
the specifically recorded FTPS/database-grant remediations were executed
outside that sandbox. A disposable full Ubuntu/OLS/MariaDB/mail/systemd lab,
fresh-install/upgrade/rollback drills, and browser security checks are still
required for the plan's completion standard. The online npm advisory request
was rejected by automatic approval review; the offline npm audit found no
cached advisories and cannot stand in for a current advisory check.

The broader existing handler suite includes tests that write service files
under `/etc/systemd/system` and certificate paths. Those fail under this
sandbox's read-only host mounts; they require the isolated full-system lab.
