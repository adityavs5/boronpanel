# CHECKPOINT run-a-8 — API documentation

**Goal:** Swagger UI at `/api/docs` (admin session required). ReDoc at
`/api/redoc`. Add descriptions + examples to undocumented endpoints. Export
`openapi.json` to `docs/api/openapi.json`.

## What was built

- **Admin-gated docs.** FastAPI's built-in docs are now DISABLED
  (`docs_url=None, redoc_url=None, openapi_url=None`) — previously
  `/api/docs` served Swagger UI to *anyone* and `/openapi.json` was public.
  Re-exposed behind an admin-session gate:
  - `GET /api/openapi.json` — the schema (`app.openapi()`), `require_admin`.
  - `GET /api/docs` — Swagger UI, `require_admin`.
  - `GET /api/redoc` — ReDoc, `require_admin`.
  The default `/openapi.json` now 404s (verified in tests). Swagger UI/ReDoc
  run in the admin's browser and fetch the schema with the same `fh_session`
  cookie (same-origin), so a signed-in admin sees the docs and no one else
  can even read the schema.
- **Offline, no CDN.** `get_swagger_ui_html`/`get_redoc_html` default to
  jsdelivr + Google Fonts CDNs — both blocked by this project's CSP and
  both breaking the "panel renders offline" principle (README §7b). Instead
  the UI bundles are **vendored** into `static/apidocs/`
  (`swagger-ui-dist@5.32.8`, `redoc@2.5.3`; provenance + refresh recipe in
  `static/apidocs/README.md`), served same-origin via the existing
  `/static` mount, and `with_google_fonts=False`. A test asserts the served
  HTML references `/static/apidocs/...` and contains no `cdn.jsdelivr.net`
  or `fonts.googleapis.com`.
- **CSP.** `/api/docs` and `/api/redoc` get a dedicated, docs-scoped CSP in
  `_security_headers` (`script-src 'self' 'unsafe-inline'; worker-src
  'self' blob:; ...`) — the minimum Swagger UI/ReDoc need (their bootstrap
  is an inline script; ReDoc uses a blob worker). Every other page keeps
  its stricter `script-src 'none'`/`'self'`.
- **Descriptions.** App-level `description` (auth model + how to use the
  docs) and `openapi_tags` with a one-line description per functional group
  (accounts, plans, dns, mail, monitoring, admin-logs, branding,
  onboarding, …). Per-endpoint descriptions come from each handler's own
  docstring/summary, which FastAPI reads automatically — the majority of
  handlers in this codebase already carry docstrings, so the rendered docs
  are populated without a mechanical per-route edit pass. Request/response
  *examples* are auto-generated by FastAPI from the Pydantic body models and
  response types (every write endpoint has a typed `BaseModel` body).
- **Export.** `scripts/export_openapi.py` imports the real app and writes
  `docs/api/openapi.json` (pretty-printed, key-sorted so diffs are stable).
  Committed artifact: **214 paths**. Re-run after any route/model change.
- **Discoverability.** Admin nav gains an "API Docs" entry (Integrations
  section) that opens `/api/docs`. Because that's a server-rendered page,
  not a client route, `Sidebar`/`NavItem` gained an `external` item kind
  that renders a real `<a target="_blank">` instead of a react-router
  `NavLink` (which would 404 in the SPA).

## Tests

`tests/test_apidocs.py` — 6 tests: schema endpoint requires admin
(401/403), the built-in `/openapi.json` is disabled (404), the schema is
served to admins with the expected title and a representative spread of
paths present (`/login`, `/api/v1/admin/plans`,
`/api/v1/admin/monitoring/settings`, `/api/v1/admin/logs/errors`, >150
total), Swagger UI requires admin and (for admins) references the vendored
local assets with the relaxed docs CSP and no CDN, ReDoc likewise offline
with `with_google_fonts=False`.

## What's honestly still open

- Interactive render (JS actually executing in a browser under the docs CSP)
  wasn't puppeteer-verified this pass; the HTML/asset/CSP wiring is the
  standard FastAPI offline-docs recipe and is asserted by tests, and the
  exported `docs/api/openapi.json` is a complete offline API reference on
  its own.
- A duplicate-operation-id warning is emitted for the FileBrowser proxy
  route (one handler bound to multiple methods); it's benign (schema still
  generates cleanly) and pre-existing to this feature.
